# API Enablement, Technical Demos, and MCP Evaluation

## Context

Technical products get adopted when users can connect them to the workflows they already have. For many customers, that means using an API, integrating results into their own tools, or increasingly, reaching product knowledge through AI assistants. Each of those paths has its own friction points, and each needs clear guidance, working examples, and a product that is usable from the outside.

My work in this area spans customer-facing technical enablement and product-side input: API demos and guidance at IMPLAN, an evaluation of IMPLAN's MCP server, and earlier API design and documentation work for GAUSS at Aptech.

---

- **Lead and contribute to:** API education, technical demonstrations, developer-oriented enablement, and customer guidance on technical workflows at IMPLAN.
- **Evaluated and advised on:** IMPLAN's MCP server, with recommendations on usability, performance, and AI-ready knowledge access. I did not build the MCP server and do not own the MCP product.
- **Earlier (Aptech):** helped design, document, and teach user-facing APIs for GAUSS modeling tools.

---

## Approach

- Start with the workflow the user is trying to complete.
- Treat usability as part of enablement: if an interface is hard to use, better documentation only goes so far.
- Explain the concepts and constraints behind the tool, not just the syntax.
- Use examples close enough to real work to build confidence.
- Provide multiple entry points: quickstart, demo, conceptual explanation, reference documentation, and deeper tutorial.
